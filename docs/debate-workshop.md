# Debate Workshop Feature

The debate workshop is a separate, buildless page at `debate.html`. The admin feature selector is `admin.html`; the member lobby is `index.html`. It shares the club member roster but stores workshop state under `/debate_sessions`, separate from book voting data. The current unfinished session ID is published at `/active_debate_session` as soon as the session is created. The lobby advertises it only after the host starts Round 1.

## Entry modes

- Host: `debate.html?mode=host&admin=1` (requires the authorized Google account)
- Projection: generated by the host for the active session
- Participant: scan the session QR code or open the generated join link

The admin route requires the configured Google account UID in the client. Realtime Database Security Rules must also restrict admin writes to that UID; a browser check alone is not a security boundary.

## Module ownership

- `assets/js/debate/config.js` — Firebase configuration and initialization.
- `assets/js/debate/session-service.js` — Realtime Database subscriptions and writes.
- `assets/js/debate/i18n.js` — EN/DE text and workshop rules.
- `assets/js/debate/views.js` — role-specific markup and state rendering.
- `assets/js/debate/app.js` — route selection, application state, and event coordination.
- `assets/css/debate.css` — page-level styles shared by the three modes.

The page uses native ES modules and relative URLs. It requires no package manager, bundler, or build step.

## Session flow

The host enters one statement per round and three reflection questions in the Settings tab. Host, secretary, and session notes are in a separate internal card in that tab, saved with the session but never rendered on member screens. The host and secretary come from the shared voting roster. The Settings tab also contains a bounded speaking timer setting: 3–30 whole minutes per person, with 3 minutes as the default for new and legacy sessions. A changed duration applies to subsequent speaking turns; an active or paused turn retains its remaining time. The chosen duration is stored under the debate session's `settings/turnDurationMs` and included in history. Members choose their roster name in the lobby; that identity carries into the event, and the debate page joins the selected member automatically. Round 1 choices can be changed; Round 2 choices are written once. The Control tab shows Round 1 above Round 2, each with explicit Start and End buttons plus per-speaker start, pause, resume, and finish controls. Ending Round 1 unlocks Start Round 2; ending Round 2 unlocks reflection. Ending a round with unfinished turns requires confirmation. Ended or not-yet-active rounds remain dimmed. The admin sees a centered, simplified live projection preview, plus joined and currently online member counts. The History tab is separate from Control. The projection shows aggregate side counts, the current statement, speaker, timer, and the session's reflection questions. Members can join during reflection and see those questions on their own screens. The member and projection routes show a generic unavailable message when a session ends. Round 2 rule 3 remains unspecified until the club supplies it.

Member presence is stored per browser tab under each session's `presence` node. Each tab registers a Realtime Database disconnect cleanup, and page exit attempts immediate cleanup. The admin count includes distinct members with at least one connected tab; `participants` remains the historical set of members who joined, even after they leave. The online count reflects the database connection state and may lag briefly when a network connection disappears unexpectedly.

The internal card is hidden from member and projection views, but the current Realtime Database session record still contains its fields. The deployed database rules must be reviewed before treating notes as confidential; strict confidentiality requires an admin-only data path and a session-data migration.

The host route first checks `/active_debate_session` and reopens its unfinished session, even when entered again from `admin.html` without a session ID. Starting another session is only possible after the current one ends. Ending writes `endedAt`, changes the session status to `ended`, and clears the current-session pointer. Completed records remain under `/debate_sessions` and appear in the host dashboard's history with statements, roles, participants, choices, completed turns, reflection questions, and notes. Realtime Database rules must allow the authorized admin to read the session collection for history and to update the current-session pointer.
