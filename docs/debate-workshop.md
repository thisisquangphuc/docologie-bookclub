# Debate Workshop Feature

The debate workshop is a separate, buildless page at `debate.html`. It shares the club member roster but stores workshop state under `/debate_sessions`, separate from book voting data.

## Entry modes

- Host: `debate.html?mode=host&admin=1234`
- Projection: generated by the host for the active session
- Participant: scan the session QR code or open the generated join link

The query code currently gates the host interface in the browser only. It is not authentication or a security boundary; configure Realtime Database rules and real authentication before relying on host-only permissions.

## Module ownership

- `assets/js/debate/config.js` — Firebase configuration and initialization.
- `assets/js/debate/session-service.js` — Realtime Database subscriptions and writes.
- `assets/js/debate/i18n.js` — EN/DE text and workshop rules.
- `assets/js/debate/views.js` — role-specific markup and state rendering.
- `assets/js/debate/app.js` — route selection, application state, and event coordination.
- `assets/css/debate.css` — page-level styles shared by the three modes.

The page uses native ES modules and relative URLs. It requires no package manager, bundler, or build step.

## Session flow

The host enters one statement per round and creates a session. Members join from the shared roster. Round 1 choices can be changed; Round 2 choices are written once. The host chooses each speaker and operates the three-minute timer. The projection view shows only aggregate side counts, the current statement, speaker, timer, and reflection questions. Round 2 rule 3 remains unspecified until the club supplies it.
